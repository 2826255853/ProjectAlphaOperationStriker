# Project Alpha Operation Striker｜简版游戏策划案

日期：2026-10-11  
依据：当前工作区代码，以及经济系统、墙面陷阱、对空导弹和投影枪四份 Plan。  
说明：“已有”表示源码已有实现，不等于本次已验证运行效果；“建议”表示后续设计。数值采用代码默认值或 Plan 记录的调试值，场景与资源配置可能覆盖。

## 1. 游戏定位

一款面向 PC 的第一人称射击与陷阱塔防游戏。玩家在多条怪物进攻路线之间移动，用有限金币布置自动防线，再亲自开枪处理漏怪和紧急威胁，保护防守核心。

核心体验是“亲自上阵的防线指挥者”：射击帮助玩家渡过布防不足的阶段，陷阱承担持续输出，地面与空中进攻迫使玩家调整配置。首版建议以单人、一张完整关卡为目标。

## 2. 一局怎么玩

开始游戏 → 观察路线并布置初始陷阱 → 敌人按波次进攻 → 玩家射击、转移支援并赚取金币 → 在波次间隙补充或调整陷阱 → 守完全部波次。

- **胜利：** 所有出怪口完成波次、场上敌人清空，核心仍存活；当前已有结果判定。
- **失败：** 核心生命耗尽；当前已有判定，并停止继续出怪。
- **玩家死亡：** 当前代码会进入观察模式，默认约 3 秒后复活。防守的最终目标仍是保护核心。
- **局内成长：** 将击杀所得投入防线，从依靠手动射击逐步过渡到射击与陷阱协同。

## 3. 已有内容与玩法分工

| 内容 | 当前基础 | 策划用途 |
| --- | --- | --- |
| 第一人称战斗 | 移动、枪械射击、武器伤害差异、距离衰减与弱点倍率 | 处理漏怪，支援输出不足的路线 |
| 地面敌人 | 沿路径向核心移动，并有攻击玩家、陷阱的战斗逻辑 | 形成正面防守压力，让站位与陷阱耐久有意义 |
| 飞行敌人 | 独立空中出怪与飞行移动，不使用地面路径网格 | 引入对空需求，打破只布地面陷阱的单一解法 |
| 哨戒机枪 | 自动选靶、持续射击与冷却 | 承担防线的常规持续输出 |
| 地刺陷阱 | 贴地放置、触发攻击与冷却 | 在允许铺设的道路位置拦截地面敌人 |
| 双联导弹发射器 | 默认只打飞行怪，预测拦截点、双发齐射、装填与爆炸伤害 | 承担专门的对空防守 |
| 陷阱布置 | 菜单、预览、占格、购买、移除与瞄准血条 | 让玩家清楚能放哪里、花多少钱、陷阱是否危险 |
| 墙面网格 | 已有安装类别、贴墙坐标、支撑校验与创作工具 | 后续利用道路侧面空间；正式墙面攻击陷阱仍需设计 |
| 地图与流程 | 三路汇合地图、波次管理、开始/暂停菜单、胜负状态 | 构成首个完整试玩关卡的基础 |

MapForge 已有地图导入和实时同步能力，可用于快速调整道路、平台与布防空间。它服务于关卡制作，无须成为玩家学习负担。

## 4. 局内经济

金币用于购买陷阱。玩家射击与陷阱击杀共用一个钱包；漏怪没有击杀奖励，并按现有规则损伤核心。选择、预览或放置失败不扣款，只有成功购买并放置才扣款。

| 项目 | 当前调试规则 |
| --- | --- |
| 初始资金 | 默认 100 金币 |
| 击杀地面怪 / 飞行怪 | 默认奖励 10 / 15 金币，可由出怪口覆盖 |
| 三种正式陷阱 | 经济 Plan 记录均为 40 金币，实际以各定义资产为准 |
| 波次奖励 | 当前代码按出怪口结算，基础曲线为第 1 波 25，之后每波增加 15 |
| 提前呼叫奖励 | 已有代码，默认每秒 2 金币、单次上限 40；实际结算与各出怪口等待状态关联 |
| 主动出售 | 当前默认回收价格的 50%，向下取整；普通拆除不退款 |

开局 100 金币按 40 的价格可购买两个陷阱，留下 20。建议让首轮的“买两座机枪”与“机枪配地刺”都能通过玩家射击完成防守，随后引入飞行怪，让对空支出成为明确选择。

这些数值尚未代表平衡完成。多出怪口的波次奖励可能叠加，后续需按整张地图的实际收入检查，避免金币增长过快。

## 5. 首个试玩关卡（建议）

沿用 `THREE_ROUTE_MERGE_MAP` 的三路汇合结构：前段提供不同布防位置，汇合处提供补漏机会，让玩家在“分路提前拦截”和“集中守住汇合点”之间选择。

首个试玩建议先做 3 波教学式节奏；代码默认总波数也是 3，具体配置另行落实。目标时长暂定 5–10 分钟。

| 波次 | 建议安排 | 玩家学到的内容 |
| --- | --- | --- |
| 第 1 波 | 地面敌人为主，进攻压力较低 | 射击、布防、金币与核心保护 |
| 第 2 波 | 增加另一条路线的压力，引入少量飞行敌人 | 转移支援、识别空中威胁并补充导弹发射器 |
| 第 3 波 | 地面与空中混合进攻，多路线同时施压 | 运用已有防线、补漏与调整投资 |

波次间隙用于查看金币、陷阱血量和薄弱路线。提前呼叫下一波可作为熟练玩家的节奏选择。敌人数量、间隔与飞行比例按试玩调整，不在本策划案中锁死。

| 局内经济 | Plan 已记录基础闭环完成；当前代码还加入了波次奖励与出售 | 对照多路线实际收入调整价格和奖励，更新旧范围描述 |
| 对空导弹 | 旧 Plan 标为待实现，当前已有武器、预测与弹道代码 | 验收飞行波次中的实际效果与目标反馈 |
| 墙面陷阱 | 旧 Plan 标为待实施，当前已有墙面放置基础 | 完成正式墙面攻击陷阱的选型，并验证地图同步和放置体验 |
| 放置投影枪 | 本次查看范围未发现专用控制器，作为待实施项 | 放置时显示手枪形投影设备，左键放置，退出后恢复原武器 |

投影枪第一版沿用 Plan：右键只保留接口，不增加具体功能；先使用独立第一人称模型，不接手部骨骼动画。它的作用是让布防模式容易辨认，并防止一次点击同时放置和射击。接入时需处理当前右键拆除交互，保留可用的拆除入口。

## 7. 开发优先级（建议）

1. **先完成可重复游玩的闭环。** 验收开始、布防、三波战斗、胜负与重开；补齐面向玩家的结算提示和重开入口。当前已有胜负状态，完整结算界面仍需确认。
2. **完成投影枪的最小交互。** 明确菜单、放置、战斗三种状态，让放置输入与普通射击互不冲突。
3. **调整三波与经济。** 确保早期金币够形成基础防线，对空敌人出现前有合理准备机会，玩家射击能弥补部分布防失误。
4. **再扩展墙面攻击陷阱。** 先确定一种攻击机制并做测试件，验证有效后再制作正式模型和更多类别。

首版范围建议控制为一张地图、地面与飞行两类敌人、三种现有正式陷阱。更多地图、跨局养成、陷阱升级和多人玩法放在试玩反馈之后评估。

## 8. 首版验收目标

- 新玩家能在第一波理解目标、完成射击和至少一次有效布防。
- 金币、价格、无效放置原因与陷阱血量清楚可见，菜单与放置操作不会误触射击。
- 地面和飞行敌人带来不同防守需求，三种陷阱都有可观察的作用。
- 玩家死亡、陷阱损毁、核心受伤与最终失败的反馈能清楚区分。
- 能完成一局并重开，资金、敌人和界面恢复到新局状态。

建议记录通关率、核心剩余生命、各陷阱使用量和波次结束余额，用于下一轮数值调整。本次仅交付策划文档，未启动 Unity 或执行游戏测试。
