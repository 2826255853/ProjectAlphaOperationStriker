# 墙面陷阱与指定墙面网格实施 Plan

状态：待实施。2026-09-22 创建；本次仅交付设计，不修改运行时代码或场景。

## 目标

- 新增墙面陷阱类别，只允许放置在明确标记的墙面陷阱网格。
- 为关卡作者提供墙面网格创建、可放置格绘制与校验能力。
- 接入现有陷阱选择、预览、占格、移除与血条流程，并兼容已有地面陷阱。

## 一、范围与默认选择

- “墙面陷阱”表示安装类别，与伤害、攻击方式、对空/对地筛选分离。
- 第一阶段支持静态、竖直、平整的指定墙面；可绕世界竖直轴任意转向。一面墙可以标记多个不重叠矩形区域，墙两侧须分别创建网格。
- 普通墙壁默认不可放置。关卡作者必须创建墙面网格并开启可放置格；窗洞、边缘和装饰障碍可以刷成禁用格。
- 默认每格 1 米、创建尺寸 4 列 × 3 行、表面显示偏移 0.01 米；尺寸均可编辑。首版墙面网格要求世界缩放为正且为单位缩放，不支持倾斜、剪切或运行时移动的墙。
- 默认陷阱占 1×1 格，另用 2×2 示例验证多格放置。首版不提供玩家手动旋转，自动朝墙外；后续若加入 90° 旋转，必须同时交换占格宽高并序列化旋转状态。
- 提供可选择、预览、放置、拆除、受伤和销毁的墙面安装测试件，用简单几何标明朝外方向。具体箭矢、喷火等攻击行为与正式美术资源另行确定，不擅自选定武器机制。
- Unity 创作工具和放置闭环为第一阶段；MapForge 原生墙面标记为第二阶段。第一阶段就必须防止现有同步误删墙面网格。

## 二、现有实现与必须兼容的地方

已核对以下实现：

- `TrapDefinition.cs` 已有占格尺寸、`LocalRotation`、`WalkableFloorTrap` 和固定世界尺寸换算。工作区包含尚未提交的地刺改动，实施时基于这些改动增量扩展。
- `TrapPlacementGrid.cs` 已负责可用格、占格、批量放置和场景重载后的占格恢复；网格目前使用本地 X/Z 平面。
- 现有生成、预览及重建流程使用 `definition.LocalRotation` 作为世界旋转，直接竖起网格不能让陷阱正确贴墙。
- `TrapPlacementController.ResolveGridForRay` 当前优先选择可用网格，没有在该方法内限制物理遮挡；墙面放置必须防止越过近墙选中远墙。
- `TrapPlacementGridEditor.cs` 已有刷格、批量铺设和校验入口，可扩展，不另写独立占格系统。
- `MapForgeWorldImporter.RebuildTrapPlacementGrids` 当前会销毁父节点下所有 `TrapPlacementGrid`，这是墙面网格接入前必须修复的生命周期风险。

注意：现行源码对地面陷阱采用网格交点和模型偏移补偿；技能文档仍有格心描述。此次不改变地面坐标语义，墙面规则单独明确，避免把旧炮塔和地刺移位。

## 三、数据设计

新增 `Assets/Scripts/TowerDefense/TrapMountType.cs`，定义 `Ground = 0`、`Wall = 1`。同一枚举用于陷阱的安装类别和网格的表面类别，避免两套类型映射。

| 所在类 | 拟新增字段或接口 | 用途 |
| --- | --- | --- |
| `TrapDefinition` | `mountType`，默认 Ground | 控制允许的安装面；旧资产缺字段时自然沿用地面 |
| `TrapPlacementGrid` | `surfaceType`，默认 Ground | 显式标识地面/墙面，不靠对象名字或旋转角猜测 |
| `TrapPlacementGrid` | `supportCollider` | 墙面网格绑定的静态墙体碰撞体 |
| `TrapPlacementGrid` | `surfaceOffset`，默认 0.01 米 | 墙面贴合及网格绘制偏移；保留旧 `placementHeight` 的地面语义 |
| `TrapPlacementGrid` | `SupportsDefinition` | 统一类型匹配；Wall 与 WalkableFloorTrap 同时开启视为无效配置 |
| `TrapPlacementGrid` | `GetPlacementPose`、`GetCellCorners`、`SurfaceNormal` | 为生成、预览、重载、Gizmo 和刷格提供相同坐标依据 |

继续复用 `TrapInstance` 的定义、原点格、血量和 OwnerGrid。每个墙面网格使用自己的实例父节点，禁止多个网格共享一个会被重复扫描的 `trapParent`。第一阶段不增加独立墙面陷阱实例类。

## 四、墙面网格空间规则

墙面网格使用自身本地 X/Y 平面：X 向右、Y 向上、+Z 朝墙外。Transform 原点位于可编辑矩形区域左下角。作者点击墙面获得法线，工具将网格的 +Z 对齐法线，+Y 对齐世界上方。

- 单格中心：`(x + 0.5, y + 0.5) × cellSize`；坐标换算用网格逆变换，再对 X/Y 向下取整。
- 多格陷阱挂点：`(origin.x + width/2, origin.y + height/2) × cellSize`，沿 +Z 加表面偏移。
- 墙面模型约定：根节点位于背板中心，+Z 朝外，+Y 朝上。墙面世界旋转使用 `grid.rotation * definition.LocalRotation`；LocalRotation 只用于模型轴修正，默认零。
- 地面保留原有位置和旋转结果；统一接口内部按 surfaceType 分支，不能直接给所有旧陷阱乘网格旋转。
- 所有墙面生成路径（预制体、缺失预制体的备用模型、批量铺设、占格恢复）与预览使用同一个 Pose 计算。
- 墙面碰撞体按背板宽、高、厚度构造，不复用地面炮塔的竖直盒体尺寸。测试件提供明确碰撞体；模型局部修正不能让拾取碰撞体与外观分离。

## 五、放置与选中规则

统一在 `CanPlaceTrap` 中完成放置校验，编辑器刷陷阱、运行时单次/拖动放置、批量原子放置全部复用：

1. 陷阱安装类别匹配网格表面类别，且网格启用、墙体引用有效。
2. 完整占格范围在边界内，全部开启且没有占用；不得跨两个网格拼接放置。
3. 墙面支持检测沿 -SurfaceNormal 采样，每个占用格的中心和略向内缩的四角须命中绑定 supportCollider，且命中法线与网格法线一致。默认检测距离 0.1 米、角度容差 5°，作为可配置参数；有洞、脱离墙面或倾斜超限时失败。
4. 检查陷阱实体安装包围盒，排除自身预览和绑定墙体，拒绝与其他陷阱、墙角突出物、玩家等实体重叠。安装包围盒应显式配置，不能只靠 Renderer 的视觉包围盒；效果范围不计为实体。
5. 墙面陷阱不写入地面道路可放置掩码，也不改变 `MonsterPathGrid`。其实体不得侵入怪物行走通道的净空；沿用现有道路格数据和怪物通行尺寸做交叉校验。攻击覆盖区域可以朝向道路。

选中和遮挡采用以下规则：

- 鼠标射线先取得最近物理遮挡距离，再判断兼容的有限网格平面；预览、网格标记与触发器不遮挡，真实墙体遮挡。
- 只允许从墙面正面放置：`dot(ray.direction, SurfaceNormal) < 0`，并受现有交互距离约束；若没有统一距离配置，则新增默认 6 米的墙面放置距离。
- 支撑墙本身的命中距离允许与网格平面有小量偏移误差，不能因此把所有合法墙面判为遮挡；该容差不得用于穿过另一堵墙。
- 最近可见墙面若被占用或禁用，显示当前失败原因，不能跳到后面的可用墙面。
- 放置只显示匹配类别的网格；拆除和血条选中独立于当前所选陷阱类别，依旧可以操作已有的地面或墙面陷阱。
- 拖动铺设跨网格时重置起点，不能连接两面墙上的格坐标。
- 预览有效为绿色，无效为红色，并显示“仅限墙面 / 网格未开放 / 已占用 / 支撑不足 / 实体冲突 / 超出距离”等原因。点击时再次校验，失败不创建实例。

## 六、Unity 创作流程与界面

新增 `Assets/Editor/WallTrapGridAuthoring.cs`，提供菜单 `Tools/Tower Defense/Create Wall Trap Grid`：

1. 选择静态墙体，在 Scene 视图点击目标面，显示法线箭头与网格预览；法线不符合竖直墙面条件则提示原因。
2. 设置网格宽高、每格尺寸和区域起点，确认后创建绑定墙体的网格；初始全部禁用，作者明确刷出允许安装的位置。
3. 复用现有刷格、擦除、填充和陷阱绘制功能，所有几何绘制走网格平面接口；支持 Undo/Redo。
4. 编辑器校验检查支撑引用、正反面、缩放、禁用格、网格重叠、通道净空和已有实例占格；地面网格校验按表面类别分支，不能对墙面应用地面半格偏移规则。
5. 修改网格尺寸/支撑面前检查已有陷阱；有实例失效时拒绝该修改并列出对象，不静默移动或删除。

`TrapSelectionMenu` 显示“地面 / 墙面”标签，并将墙面占格描述为“宽 × 高”。沿用 N 菜单、4–7 槽位、左键放置、右键/E 拆除与 Esc 退出。保留 `TrapSelectionMenu.CursorOwned` 的视角锁定和武器输入保护。

## 七、MapForge 接入与生命周期

第一阶段必须完成保护：

- `RebuildTrapPlacementGrids` 只重建由导入器管理的地面网格，不能按组件类型全删。用明确的生成来源标识识别所有权；旧自动网格采用受限的迁移识别。
- Unity 手工墙面网格放在独立的创作根节点下，保持对支撑墙的引用；普通增量同步不删除它们。
- 墙体移动、缩放或被替换时，使绑定失效或重新校验；失效网格禁止放置并报出具体对象，不能悬空继续使用。全量重建墙对象后通过稳定对象 ID 重新绑定；重新绑定失败保留网格并报错。
- 场景修改前保留可撤回版本；验证同步后手工空中出怪口、地面网格和墙面网格均符合各自保留规则。

第二阶段为 MapForge 增加原生创作能力（外部编辑器源码本次未读取，以下为拟定协议）：

- 在墙对象上新增 `unity.wallTrapGrids[]` 可选字段，包含网格稳定 ID、局部原点与旋转、columns、rows、cellSize、surfaceOffset、openCells。
- 墙对象既有稳定 ID 作为支撑对象 ID；区域可多个，每个区域独立正反面、占格和掩码。
- `C:\MapEditor` 增加选面、矩形区域和刷格交互，保存/导出及 Send to Unity 共用数据。
- Unity 按“墙对象 ID + 网格 ID”原位更新；删除指定区域只影响该区域，不影响 Unity 手工网格。非结构性更新保留 ID 与已有实例；结构性变更使实例失效时返回明确错误，不静默删陷阱。
- 旧 JSON 无此字段时不生成墙面网格；未知/非法数据报告对象 ID 与原因。若须升级传输协议，Unity 和 MapForge 同步升级版本常量。

## 九、验收标准与验证顺序

第一阶段完成须同时满足：

- 旧陷阱定义和旧网格不迁移也按地面行为运行；地刺的可通行标记、固定尺寸、地面支撑要求保留。
- 关卡作者能在任意朝向的竖直墙面创建指定区域、刷禁用格、撤销修改、保存并重新打开。
- 墙面陷阱不能放地面，地面陷阱不能放墙面；未标记墙壁始终不可放置。
- 1×1、2×2 陷阱贴墙朝外，预览与成品位置、旋转、尺寸一致；越界、重叠、孔洞、背面、遮挡和超距均拒绝。
- 同一堵墙两侧以及墙角附近的网格互不串格；实体跨区域冲突被拒绝。
- 删除/销毁后立即释放完整占格，保存重开与域重载后实例不转回地面、不移位、不重复占格。
- 实例可以用现有操作拆除，血条显示正常；幽灵预览不能造成伤害或成为可受伤的正式陷阱。
- 地面炮塔、地刺、平台陷阱和怪物通路回归通过；新增墙面实体不阻挡道路，地面近战怪不会因选择无法接近的高墙陷阱而停滞（若发现该问题，只修正必要的可达性筛选）。
- Send to Unity 更新普通几何后墙面网格不会被地面网格重建删除；支撑墙失效时有明确提示。

验证顺序：类型/坐标/多格占用与销毁的 EditMode 测试 → 真实 Collider 的墙面遮挡及支撑测试 → 编辑器创建、Undo/Redo、保存重开 → PlayMode 放置/拆除与地面回归 → 增量同步和全量重绑。测试放在现有 `#if UNITY_INCLUDE_TESTS` 约定内。

第二阶段增加 MapForge 导出往返、旧 JSON 兼容、ID 稳定更新、删除单个区域和同步失败回执验收。

本次为 Plan，没有启动编译或 Unity 测试。实施时遵守 30 分钟测试启动上限；到点不再启动新测试，已运行测试结束后记录已通过与未执行项目，继续产出最小可审阅修改。
