# 游戏存档系统计划

## 目标

每次对局结束时自动保存一份本地累计统计。当前版本仅记录总游玩局数、胜利局数和失败局数，不保存局内进度、玩家配置或其他数据。

## 范围

- 存档触发点：一局游戏正式结束时自动保存一次。
- 存档内容：总游玩局数、胜利局数、失败局数。
- 存档范围：本机单机存档，不涉及账号、云同步、跨设备同步或存档槽位。
- 不增加手动保存、读取档位、删除存档或游戏中途恢复功能。

## 数据定义

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `totalGamesPlayed` | 整数 | 已完成对局总数 |
| `gamesWon` | 整数 | 已完成胜利对局数 |
| `gamesLost` | 整数 | 已完成失败对局数 |

统计约束为 `totalGamesPlayed = gamesWon + gamesLost`。未完成、退出或中断的对局不计入以上统计。对局结束后根据最终结果只增加胜利或失败其中一项，并将总局数增加 1。

## 保存流程

1. 由现有对局流程确认本局进入正式结束状态，并取得最终胜负结果。
2. 对同一局执行一次性结算，避免结束事件重复触发导致重复计数。
3. 读取已有统计，增加总局数，并按结果增加胜利局数或失败局数。
4. 持久化更新后的三项统计，并确保写入完成后再允许开始下一局或展示结算完成状态。
5. 游戏启动时读取存档；首次运行或存档不可用时以 `0 / 0 / 0` 初始化。

## 持久化与容错

- 首版使用 Unity `PlayerPrefs` 保存三个整数，键名需采用统一前缀并保持稳定。
- 载入时校验数值非负且满足统计约束；缺失或不一致时使用默认值，并按实现策略修复存档。
- 写入完成后调用 `PlayerPrefs.Save()`，减少应用异常退出时丢失本局统计的窗口。
- 存档格式预留版本字段的扩展空间；当前三项统计不需要额外引入复杂的序列化格式。

## 实现拆分

1. 找到对局胜利、失败和结束状态的统一入口，确认结束事件是否可能重复触发，以及重开局的状态重置时机。
2. 新增轻量存档服务，负责读取、校验、更新和保存三项累计统计。
3. 在唯一的对局结算入口调用存档服务，确保胜负统计与本局结果一致。
4. 提供供结算界面或后续统计界面读取的只读统计数据接口；本阶段不要求新增统计 UI。
5. 通过隔离测试验证新档、胜利、失败、重复结算、重启后读取及无效数据恢复。

## 验收标准

- 新存档启动时三项统计均为 0。
- 一局胜利结束后，总局数和胜利局数各增加 1，失败局数不变。
- 一局失败结束后，总局数和失败局数各增加 1，胜利局数不变。
- 同一局结束流程重复通知时只累计一次。
- 关闭并重新启动游戏后，三项统计仍正确保留。
- 中途退出或未进入正式结束状态的对局不改变统计。
- 任何有效存档均满足 `totalGamesPlayed = gamesWon + gamesLost`。

## 待实现时确认

- 对局系统中胜利、失败和结束的权威状态入口，以及是否存在平局或其他结束结果。若存在其他结果，首版需定义其是否计入总局数；默认只统计胜利与失败。
- 存档键名最终命名及统计数据的 UI 展示位置。首版不因这两项阻塞数据保存实现。
