## 1. 结论摘要

1. 计划里的核心假设基本成立：`TrapDefinition` 有 `TrapId`，`TrapInstance` 持有血量，`EconomyManager` 有 `RunId` + 预约/提交机制，七类陷阱的伤害/维修都集中在可识别的单点读取位置。
2. **有 5 处与计划假设不一致，必须在第 2～7 步按本节调整实施方式**（见第 5 节），其中两条影响面较大：
   - 陷阱菜单是 **IMGUI（`OnGUI`）**，不是预制体/Canvas。第 7、8 步的「卡片右下角圆框向上箭头」「确认窗口」「方向选择窗口」只能以 IMGUI 方式实现。
   - 存在 **两份同名 `TrapId` 的定义资产**（`Assets/Resources` 与 `Assets/TrapDefinitions`），第 2 步的「同一 TrapId 不允许静默合并不一致配置」必须先决定以哪份为准。
3. 七类陷阱的一级基础数值已从预制体读出（第 4 节表格），与计划默认规则表可以对齐；`maxHealth` 目前一律为 100，`TrapInstance.maxHealth` 就是「一级基础血量」的天然载体。

### 2.4 购买 / 放置 / 出售调用链

```
TrapPlacementController（输入、槽位、预览）
  └─ TrapPurchaseService.TryPurchase(grid, origin, definition, out instance, out failure)
       ├─ grid.CanPlaceTrap(...)                    // 唯一放置判定
       ├─ wallet.TryReserve(definition.Cost, out payment)
       ├─ grid.TryPlaceTrap(origin, definition, out instance, out failure)
       │    └─ CreateTrapObject → 补 Collider → instance.Initialize(definition, origin)
       │       → placedTraps / occupiedCells 登记
       └─ payment.Commit() → 失败则 grid.RemoveTrap(instance) 回滚
```

- `TrapPlacementGrid.TryPlaceTrap`（`TrapPlacementGrid.cs:714`）是底层放置接口；`instance` 的获取是 `root.GetComponent<TrapInstance>() ?? root.AddComponent<TrapInstance>()`（:776）。**这条 `AddComponent` 分支会让 `maxHealth` 取源码默认值 100**，第 4 步必须覆盖它。
- 出售：`TrapSaleService.TrySell`（`TrapSaleService.cs:52`）→ `wallet.Grant(refund)` → `grid.RemoveTrap(instance)`；`RefundFor` 只按 `definition.Cost × ratio` 计算，**天然不包含升级费用**，与计划「升级费用不计入退款」一致，本任务无需改。
- 已有养成钩子：`TrapSaleService.RefundRatioOverride`（:30，`Func<TrapDefinition, float?>`）。

### 2.5 受伤链

```
GroundEnemyCombat.cs:102  trapTarget.TakeDamage(attackDamage)
  → TrapInstance.TakeDamage → CurrentHealth 下降 → Damaged
  → 归零：activeTraps 移除 → Destroyed → OwnerGrid.RemoveTrap → Destroy(gameObject)
```

`TrapInstance` 自身不区分伤害类型，也不做抗性结算（陷阱不是 `EnemyHealth`）。

## 3. 七类陷阱攻击/维修脚本的伤害读取点

所有伤害都走 `EnemyHealth.TakeDamage(amount, TrapDamageType)`，`TrapDamageType` 是 `DamageType` 的兼容映射层。

| 陷阱 | 脚本 | 读取点（行号） | 调用形态 |
| --- | --- | --- | --- |
| 机枪 | `AutoSentryTurret` | `FireAtTarget` :246 | `health.TakeDamage(damagePerShot, TrapDamageType.Bullet)`，**每发读取** |
| 地刺 | `GroundSpikeTrap` | `HasContact` :130 | `enemy.TakeDamage(damage, TrapDamageType.Melee)`，每轮攻击 `hitThisAttack` 去重 |
| 双联导弹 | `MissileLauncherWeapon` → `MissileProjectile` | `LaunchOneMissile` :409 `missile.ConfigureTuning(damagePerMissile, …)`；命中 `MissileProjectile.cs:327 / 340 / 353` | 伤害在**发射时写入弹体**，溅射 `damage × splashDamageRatio` |
| 喷火器 | `FlamethrowerTrap` | `ApplyBurstDamage` :126-127 | `TakeDamage(directDamage, Fire)` + `FireStatusEffect.Ignite(enemy, burnDuration, burnDamagePerSecond)` |
| 贝蒂7号 | `Betty7JumpMineTrap` | `DamageAround` :404 | `enemy.TakeDamage(damage, TrapDamageType.Explosive)`，**起爆时读取字段** |
| 扼喉之灯 | `ThroatLampTrap` → `PlasmaProjectile` | 发射 `Advance` :103 `shot.Initialize(…, directDamage, splashDamage, …)`；结算 `PlasmaProjectile.cs:75` | 伤害在**发射时写入弹体**，直击/溅射分别取字段 |
| 维修站 | `RepairStationTrap` | `Tick` :118 | `target.Repair(repairAmount) > 0f`，每臂 `readyAt[i]` 独立冷却 |

补充事实：

- 导弹溅射比例字段 `splashDamageRatio` 与弹体 `damage` 解耦（`MissileProjectile.cs:332`），第 6 步只要在 `ConfigureTuning` 传有效伤害即可，**不需要**再乘倍率。
- `PlasmaProjectile.Impact`（:66-78）对直击目标只结算一次直击伤害，其它有效目标结算溅射 —— 与计划「直击目标不重复承受溅射」一致，现状已满足。
- `FireStatusEffect` 是挂在怪物上的独立状态（`FireStatusEffect.cs`），`Ignite` 的合并规则是「刷新时长 + 保留较高 DPS」（:60 附近）。第 6 步「已施加燃烧保留生成时伤害」必须把升级后的 DPS 作为参数传入 `Ignite`，**不能**改成在 tick 时读取等级。
